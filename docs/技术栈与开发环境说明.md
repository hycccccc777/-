### 3. 数据库

- **MySQL 26.7.0**（`C:\Program Files\MySQL\MySQL Server 26.7`）
- **Flyway 12.4.0**：结构版本化管理，`flyway_schema_history` 记录 `V1`（存量库基线）与 `V2`（订单列表索引），启动时自动校验与迁移
- **MyBatis 4.1.0 + PageHelper 4.1.1**：持久层与分页
- **Druid 1.2.28**：连接池 + SQL 监控
- 库 `shop` 共 45 张表，其中业务表 13 张（`ct_` 前缀：商品、订单、支付、退款、幂等、收藏、购物车、地址、类目、学校、图片、用户资料），其余为若依系统表与 Quartz 调度表

截图：`screenshots/06-database.png`（mysql.exe 实查：版本、业务表清单、商品/订单数量、Flyway 迁移记录）

> 安全说明：截图中数据库密码已脱敏；实际口令通过环境变量 `CAMPUS_DB_PASSWORD` 注入，不写入仓库。

### 4. 缓存

- **Redis 7.4.3**（standalone 单机模式，Cygwin 构建）
- 实际用途：
  1. **刷新令牌存储**（`RefreshTokenService`，按天过期）
  2. **登录态**（若依 `TokenService` 将令牌缓存于 Redis）
- 说明：限流器 `SlidingWindowLimiter` 采用**进程内**滑动窗口（`ConcurrentHashMap`），代码注释已写明"单实例部署足够；多实例应换 Redis + Lua 实现"，对外接口不变

截图：`screenshots/07-runtime-versions.png`（`INFO server` 返回 `redis_version:7.4.3`、`redis_mode:standalone`）

### 5. 消息队列 —— 未采用（含理由）

本项目**没有引入 RabbitMQ / RocketMQ / Kafka 等消息队列**，属于有意识的技术取舍，而非遗漏：

- 业务规模为单实例单体应用，异步解耦的收益小于引入中间件的运维成本
- 需要"保证不重复处理"的场景（下单）改用**数据库幂等表** `ct_idempotency` + 唯一约束实现，等价于"至少一次投递 + 幂等消费"的效果，且与业务事务同库、天然原子
- 支付回调、退款等流程走**同步事务 + 回调签名校验**，无跨系统最终一致性需求

若未来要上 MQ（如对接真实支付、对账、通知），接入点已在代码中预留：支付通过 `PaymentGateway` 接口抽象，替换实现即可。

### 6. 注册配置中心 —— 未采用（含理由）

**没有引入 Nacos / Eureka / Consul / Apollo**：

- 单实例部署，无需服务发现与动态配置推送
- 配置使用 **Spring Boot 外部化配置**：`application.yml` + profile（`druid`）+ 环境变量覆盖，核心凭证一律走环境变量（`CAMPUS_DB_URL` / `CAMPUS_DB_USERNAME` / `CAMPUS_DB_PASSWORD` / `CAMPUS_PAY_SECRET` / `SPRINGDOC_ENABLED`），不落仓库
- 容器场景下由 `docker-compose.yml` 的 `environment` 注入，等价于集中式配置的最小实现

### 7. 网关

- **生产/容器**：前端镜像内置 **Nginx**，对外提供静态资源，并将 `/api/` 反向代理到后端容器，形成统一入口（见 `校易淘前端…/deploy/nginx.conf.example` 与 CI 的"冒烟测试（经前端 Nginx 反代访问后端）"）
- **开发**：Vite dev server 代理 `/api`、`/profile` 到 `http://127.0.0.1:8080`，使前端与后端同源，避免跨域

截图：`screenshots/05-frontend-home.png`（前端页面经代理正常加载后端数据）

### 8. 容器

- **后端 Dockerfile**：JDK 运行时镜像，分层拷贝，非 root 用户运行
- **前端 Dockerfile**：多阶段构建（Node 构建 → Nginx 运行）
- **docker-compose.yml**：四个服务
  - `mysql:8.4`（挂载 `docker/mysql-init` 自动导入种子数据）
  - `redis:7-alpine`
  - `campus-backend`（自建）
  - `campus-frontend`（自建，Nginx）

> 说明：**本机未安装 Docker**，因此容器化未在本机演示；它由 CI 的「容器编排验证」作业在 GitHub 托管的 Ubuntu 上**真实执行** `docker compose up -d --build --wait`，并完成冒烟测试、种子数据校验、非 root 卷可写性校验后拆除。截图见 `08-ci-actions.png`。

### 9. 监控与可观测性

| 能力 | 实现 | 位置 |
|---|---|---|
| SQL / 连接池监控台 | Druid 内置监控 | `http://localhost:8080/druid` |
| 全链路追踪 | `ApiTraceFilter` 为每请求生成 `X-Trace-Id`，写入 MDC 与响应头，日志按 trace 串联 | 所有 `/api/v1` 请求 |
| 健康检查 | 自定义探活接口 | `GET /api/v1/system/health` |
| 统一错误契约 | `{code, message, data}`，异常统一映射 | 全局 advice |
| 结构化日志 | 按级别分文件（`sys-info.log` / `sys-error.log` / `api-access.log`） | `logs/` |

截图：`screenshots/02-druid-monitor.png`（Druid 监控台）、`screenshots/03-health.png`（健康检查返回）

### 10. CI/CD

**GitHub Actions**（`.github/workflows/ci.yml`），每次 push 触发三个并行作业：

| 作业 | 运行环境 | 关键步骤 |
|---|---|---|
| 后端编译与测试 | ubuntu-latest | 安装 JDK 与 MySQL 客户端 → `ci.ps1` 起 MySQL/Redis 跑全量用例（35 例）→ 校验 OpenAPI 契约无漂移 → 上传 surefire 报告 |
| 前端构建与测试 | ubuntu-latest | 安装 Node → `ci.ps1` 装依赖、跑 19 例单测、构建 → 构建前端 Docker 镜像 |
| 容器编排验证 | ubuntu-latest | `docker compose config` 语法校验 → `up -d --build --wait` 起四服务 → 冒烟测试（经 Nginx 反代访问后端）→ 校验种子数据 → 校验非 root 可写卷 → 收摊 |

截图：`screenshots/08-ci-actions.png`（最近三次运行与作业明细，取自 GitHub Actions API）
在线可复核：`https://github.com/hycccccc777/-/actions`
