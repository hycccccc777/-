# 校易淘 · 数据库设计说明

数据库：`shop`（utf8mb4 / utf8mb4_general_ci）
脚本目录：`RuoYi-Vue-master/RuoYi-Vue-master/sql/`

导入顺序：`ry_20260417.sql` → `quartz.sql` → `campus_trade.sql` → `campus_menu.sql` → `campus_seed_products.sql`

---

## 一、设计原则

1. **用户复用若依 `sys_user`**，不新建用户表。登录按 `phonenumber` + `password` 校验；昵称取 `nick_name`，头像取 `avatar`，角色/权限沿用若依体系。
2. **校园专属信息独立存放**：学校、学号、认证状态放在 `ct_user_profile`，不污染 `sys_user`。
3. **业务表统一 `ct_` 前缀**，状态字段用 `char(1)` 短码，中文含义由若依字典（`sys_dict_type` / `sys_dict_data`）提供。
4. **金额统一 `decimal(10,2)`**，一律由服务端计算，前端传入金额不作为依据。
5. **订单保存快照**：收货人、电话、地址、订单明细（标题/封面/成交价）全部冗余保存，历史订单不受商品后续修改影响。
6. **逻辑删除**：主数据（商品、类目、学校、地址、订单、退款）使用 `del_flag`（0存在 2删除）；从属数据（订单明细、图片、收藏、购物车、支付单）为物理删除。

---

## 二、表关系概览

```
sys_user (若依)
   │ 1
   ├─ N  ct_user_profile   校园档案（学校/学号/认证状态）
   │  1
   ├─ N  ct_product ──1:N── ct_product_image
   │  1
   ├─ N  ct_cart_item      （唯一索引 user_id + product_id）
   │  1
   ├─ N  ct_favorite       （唯一索引 user_id + product_id）
   │  1
   └─ N  ct_address

ct_order ──1:N── ct_order_item
   │ 1
   ├─ 1:1 ct_payment      （支付单）
   └─ 1:N ct_refund        （退款/售后单）

ct_school   1 ── N ct_product、ct_address
ct_category 1 ── N ct_product（预留多级：parent_id）
```

## 三、业务表清单（12 张）

### 1. `ct_school` 学校表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| school_id | bigint PK | 学校 ID |
| school_name | varchar(64) | 学校全称 |
| short_name | varchar(32) | 简称（前端「本校 / 邻校」筛选按此字段匹配） |
| city | varchar(32) | 所在城市 |

### 2. `ct_category` 商品类目表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| category_id | bigint PK | 类目 ID |
| parent_id | bigint | 父类目，0 为根 |
| category_name / icon | varchar | 类目名 / 前端图标名 |

### 3. `ct_user_profile` 用户校园档案表

| 字段 | 说明 |
| --- | --- |
| user_id | 唯一索引，关联 `sys_user.user_id` |
| school_id | 所属学校 |
| student_no | 学号 |
| verify_status | 认证状态：0未认证 1待审核 2已认证 3已驳回 |

> 学号审核流程尚未在 `/api/v1` 暴露，仅保留数据结构。

### 4. `ct_product` 商品表（核心）

| 字段 | 说明 |
| --- | --- |
| product_id | 商品 ID |
| category_id / seller_id / seller_type | 类目 / 卖家 / 卖家类型（0个人 1商家） |
| price / original_price | 售价 / 原价 |
| stock | 库存（归零且在售时自动置「已售出」） |
| condition_code | 成色编码，对应字典 `ct_condition` |
| school_id / location | 所属学校 / 交接地点 |
| cover_url | 封面图（取 `ct_product_image` 第一张） |
| status | 0待审核 1已上架 2已下架 3审核驳回 4已售出 |
| view_count / favorite_count | 浏览量 / 收藏数 |

**关键索引**：`category_id`、`seller_id`、`school_id`、`status`、`price`、`create_time`。

### 5. `ct_product_image` 商品图片表

`product_id` 一对多，`order_num` 控制排序，`cover_url` 取第一条。

### 6. `ct_cart_item` 购物车表

| 字段 | 说明 |
| --- | --- |
| cart_item_id | **购物车条目 ID**（对外接口的 `{cartItemId}`，与商品 ID 区分） |
| user_id + product_id | **唯一索引**，同一用户同一商品只有一条 |
| quantity / selected | 数量 / 是否选中 |

### 7. `ct_favorite` 收藏表

`user_id + product_id` 唯一索引。**当前前端仍用本地存储，未接入接口**，表结构已就绪。

### 8. `ct_address` 收货地址表

`user_id + receiver + phone + school_id + detail + is_default`。**尚无 `/api/v1` 接口**，下单时由订单表快照收货信息。

### 9. `ct_order` 订单主表（核心）

| 字段 | 说明 |
| --- | --- |
| order_id / order_no | 订单 ID / 订单号（业务唯一，`CT` + 时间戳 + 6 位随机） |
| buyer_id / seller_id | 买家 / 卖家 |
| group_no | **下单批次号（幂等键）**：一次结算拆出的多个订单共用 |
| total_amount / delivery_fee / pay_amount | 商品总额 / 配送费（暂为 0）/ 应付金额 |
| status | 0待付款 1待发货 2待收货 3已完成 4已取消 5退款中 6已退款 |
| delivery_type | 0自提 1配送 |
| receiver / receiver_phone / address_detail | 收货信息快照 |
| idempotency_key | **保留字段**（有唯一索引），当前业务未写入，实际幂等由 `group_no` + 应用层查询实现 |
| pay_time / ship_time / finish_time / cancel_time / cancel_reason | 各环节时间与取消原因 |

**拆单规则**：一次结算按 `sellerId` 分组，每个卖家生成一条 `ct_order`，共享同一个 `group_no`。

**幂等实现**：请求携带 `idempotencyKey` → 写入 `group_no`；重复提交时先按 `group_no` 查询，命中则直接返回原订单，不再校验购物车、不再扣库存。客户端键超过 64 字符会被截断。

### 10. `ct_order_item` 订单明细表

保存 `product_id + title + cover_url + price + quantity + total_amount` 快照。

### 11. `ct_payment` 支付单表

| 字段 | 说明 |
| --- | --- |
| pay_no | 支付单号（`PAY` + 时间戳 + 6 位随机），唯一 |
| order_no / user_id / amount | 订单 / 付款人 / 金额 |
| pay_method | 0沙箱 1支付宝 2微信 3余额 |
| status | 0待支付 1支付成功 2支付失败 3已退款 |
| third_party_no | 第三方流水号（沙箱为 `SANDBOX` + 随机） |

### 12. `ct_refund` 退款/售后表

| 字段 | 说明 |
| --- | --- |
| refund_no | 退款单号（`RF` + 时间戳 + 6 位随机），唯一 |
| order_id / order_no | 关联订单 |
| user_id / seller_id | 申请人（买家）/ 卖家 |
| refund_amount | 退款金额（取订单 `pay_amount`，当前不支持部分退款） |
| status | 0待审核 1已同意 2已拒绝 3已退款完成 |
| **order_status_before** | **申请前的订单状态**，卖家拒绝时用它回滚订单 |
| handle_by / handle_time / handle_remark | 卖家处理信息 |

---

### 13. `ct_idempotency` 下单幂等表

| 字段 | 说明 |
| --- | --- |
| idem_key | 客户端幂等键，**唯一索引 uk_ct_idem_key** |
| group_no | 下单批次号，创建完成后回写 |
| status | 0处理中 1已完成 |

**并发保证**：下单时先插入幂等键，只有插入成功的请求能进入下单流程；并发重复请求会命中唯一键冲突，被转为「重放原批次」或「创建中，请勿重复提交」。这使幂等从应用层查询升级为数据库级保证。

此外 `ct_order` 上还有 `unique key uk_ct_order_group_seller (group_no, seller_id)`，防止同一批次内同一卖家被重复建单。

## 五、核心业务规则

### 库存

| 场景 | 处理 |
| --- | --- |
| 加入购物车 | 校验 `status='1'` 且 `stock >= quantity` |
| 下单 | 扣减 `stock`；若 `stock <= 0` 且原为已上架 → 置为「已售出(4)」，从公开列表移除 |
| 取消订单 | **回滚库存**；若商品为「已售出」→ 恢复为「已上架(1)」 |
| 退款完成 | **回滚库存** + 恢复上架 |

### 状态流转约束

- 取消：仅「待付款」
- 支付：仅「待付款」
- 发货：仅「待发货」，且仅卖家
- 确认收货：仅「待收货」，且仅买家
- 申请退款：仅「待付款 / 待发货 / 待收货」，且仅买家；同一订单不允许重复进行中的退款
- 拒绝退款：订单回滚为 `order_status_before`
- 完成退款：需先「已同意」，且订单须为「退款中」

### 越权处理

他人订单 / 商品 / 退款单统一返回 **404**（不返回 403），避免泄露资源是否存在。

## 八、升级说明

若已按旧版脚本建过 `ct_order`，`group_no` 需要从 `varchar(32)` 扩到 `varchar(64)`（批次号 = `"G"` + 32 位 UUID）：

```sql
ALTER TABLE ct_order MODIFY COLUMN group_no varchar(64) DEFAULT NULL COMMENT '下单批次号/幂等键（一次结算的多个子订单共用）';
```

退款表 `ct_refund` 与字典 `ct_refund_status` 可从 `campus_trade.sql` 中对应段落单独导入。
