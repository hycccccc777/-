# 校易淘 · 接口文档（/api/v1）

- **Base URL**：`/api/v1`（开发环境由 Vite 代理到 `http://127.0.0.1:8080/api/v1`）
- **请求/响应**：JSON，UTF-8
- **认证**：`Authorization: Bearer <accessToken>`

## 通用约定

### 响应结构

```json
{ "code": 200, "message": "success", "data": {} }
```

> 注意字段名是 **`message`**（不是若依后台的 `msg`）。

### 错误码

| code | HTTP | 含义 |
| --- | --- | --- |
| 200 | 200 | 成功 |
| 400 | 400 | 参数或业务校验失败（如标题过短、库存不足、状态不允许） |
| 401 | 401 | 未登录 / 登录失败 / 令牌失效 |
| 404 | 404 | 资源不存在或无权访问（他人订单、商品、退款单统一返回 404） |
| 409 | 409 | 状态冲突（如重复申请退款、订单状态不可操作） |

### ID 类型

所有 `id` 在响应中以**字符串**返回（前端直接使用，避免 Long 精度丢失）。请求时商品/类目等 ID 用数字或数字字符串均可。

### 分页

列表接口返回：

```json
{ "total": 8, "page": 1, "size": 12, "list": [] }
```

### 幂等

下单接口支持幂等键：请求体 `idempotencyKey` 或查询参数 `idempotencyKey`。同一键重复提交**返回同一批订单**，不会重复扣减库存。前端在每次打开结算弹窗时生成一个键。

## 一、认证

### POST /auth/login · 手机号密码登录（匿名）

请求：

```json
{ "phone": "15888888888", "password": "admin123" }
```

响应 `data`：

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "refreshToken": null,
  "expiresIn": 1800,
  "user": {
    "id": "1", "username": "admin", "nickname": "若依", "name": "若依",
    "avatar": "", "phone": "15888888888",
    "roles": ["admin"], "role": "admin", "admin": true
  }
}
```

失败：`401 {"code":401,"message":"手机号或密码错误"}`

### POST /auth/logout · 退出登录
需认证。清除服务端令牌。前端需调用 `clearAccessToken()`。

### GET /user/info · 当前登录用户
需认证。返回结构同 `user` 字段。

## 二、商品

### GET /products · 商品列表（匿名）

查询参数：

| 参数 | 说明 |
| --- | --- |
| `keyword` | 标题模糊搜索 |
| `categoryId` | 类目 ID |
| `school` | 学校名称或简称（如「本校」） |
| `sellerType` | 0个人 1商家 |
| `condition` | 成色编码：`almost_new` / `nine` / `eight` |
| `minPrice` / `maxPrice` | 价格区间 |
| `sort` | `recommended`(默认) / `newest` / `priceAsc` / `priceDesc` |
| `page` / `size` | 分页，默认 1 / 12 |

> 公开列表**只返回已上架（status=1）**商品。`status` 可由后端强制指定，前端无需传。

列表项字段：`productId, title, categoryId, categoryName, price, originalPrice, stock, conditionCode, conditionLabel, schoolId, schoolName, location, coverUrl, tag, description, status, viewCount, favoriteCount, sellerId, sellerName, createTime`

### GET /products/{id} · 商品详情（匿名）
不存在返回 `404 {"code":404,"message":"商品不存在或已下架"}`

### GET /categories · 类目列表（匿名）
返回启用中的类目数组，字段 `categoryId / categoryName / icon / orderNum`。

### POST /products · 发布商品（需登录）

```json
{
  "title": "复古奶油色台灯 · 三档调光",
  "categoryId": 102,
  "price": 39,
  "originalPrice": 129,
  "stock": 1,
  "condition": "almost_new",
  "description": "暖光很适合晚上看书…",
  "location": "西区宿舍楼下",
  "tag": "好物推荐",
  "images": ["/profile/upload/2026/10/19/xxx.png"]
}
```

响应 `data`：`{ "id": "12", "status": "1" }`

校验：标题 4～128 字；价格 0.01～99999；`categoryId` 必填；图片最多 6 张。

> **安全提示**：`GET /api/v1/products` 使用 `@Anonymous` 放行，而若依的路径白名单**不区分 HTTP 方法**，因此同路径的 `POST /api/v1/products` 也会被放行。后端已在发布接口中**显式校验登录态**，未登录返回 `401`。

### POST /upload · 上传图片（需登录）

`multipart/form-data`，字段名 `file`。仅允许图片扩展名，单文件 ≤50MB。

响应 `data`：

```json
{ "url": "/profile/upload/2026/10/19/xxx.png", "fileName": "/profile/upload/2026/10/19/xxx.png" }
```

图片通过 `/profile/**` 静态映射访问（开发环境已配 Vite 代理）。

## 三、卖家中心

### GET /my/products · 我发布的（需登录）
可选 `status` 过滤。返回结构同商品列表项。

### PUT /my/products/{id} · 编辑商品（需登录）
请求体可含 `title / price / stock / description / location / tag`（仅传需要修改的字段）。
已售出商品不可编辑 → `409`。

### PUT /my/products/{id}/status?status=1|2 · 上架 / 下架（需登录）
`status` 只允许 `1`（上架）或 `2`（下架），其他值 `400`。已售出不可操作 `409`。

### DELETE /my/products/{id} · 删除商品（需登录）
软删除（`del_flag=2`）。已售出不可删除 `409`。

## 四、购物车

| 接口 | 说明 |
| --- | --- |
| `GET /cart` | 我的购物车（含商品摘要、卖家、库存） |
| `POST /cart/items` | 加入购物车，请求 `{ "productId": 1, "quantity": 1 }`；已存在则累加数量 |
| `PUT /cart/items/{cartItemId}` | 修改数量，请求 `{ "quantity": 2 }` |
| `DELETE /cart/items/{cartItemId}` | 移出购物车 |

> **`{cartItemId}` 是购物车条目 ID，不是商品 ID。** 这是最容易出错的地方。

校验：商品须已上架（否则 `409`）、库存充足（否则 `409 商品库存不足`）、不能购买自己发布的商品（`400`）、条目不属于当前用户（`404`）。

购物车项返回：`{ id, cartItemId, productId, quantity, selected, product: { id, title, price, originalPrice, coverUrl, conditionLabel, schoolName, location, sellerId, sellerName, status, stock } }`

## 五、订单

### POST /orders · 下单（需登录）

```json
{
  "cartItemIds": ["10", "11"],
  "receiver": "张三",
  "phone": "13800002000",
  "addressDetail": "本校西区 3 号楼",
  "deliveryType": "0",
  "remark": "尽快联系",
  "idempotencyKey": "ck-1730000000-abc123"
}
```

也支持传 `addressId`（有地址管理接口后优先），此时忽略上面三个收货字段。

响应 `data`：**按卖家拆单**

```json
{
  "groupNo": "ck-1730000000-abc123",
  "orders": [
    { "orderNo": "CT20260101120000A1B2C3", "sellerId": "1001", "sellerName": "小林同学",
      "status": "0", "statusText": "待付款", "totalAmount": 25.00, "payAmount": 25.00 }
  ]
}
```

行为说明：
- 按 `sellerId` 分组，每个卖家生成独立订单，金额由服务端重算
- 下单扣减库存；库存归零则商品置「已售出」并从公开列表移除
- 下单成功后对应购物车条目自动移除
- 相同 `idempotencyKey` 重复提交返回同一批订单

### GET /orders · 我买到的（需登录）
`data` 为订单数组，单项字段：`orderNo, status, statusText, deliveryType, totalAmount, deliveryFee, payAmount, receiver, receiverPhone, addressDetail, remark, sellerId, sellerName, createTime, items[]`（`items` 含 `productId,title,coverUrl,price,quantity,totalAmount`）。

### GET /orders/sold · 我卖出的（需登录）
同结构，按卖家维度返回。

### GET /orders/{orderNo} · 订单详情（需登录）
买家或卖家可见。

### PUT /orders/{orderNo}/cancel · 取消订单（需登录，仅买家）
仅「待付款」可取消。取消后**恢复库存**，商品重新上架。其余状态 `409`。

### PUT /orders/{orderNo}/ship · 发货（需登录，仅卖家）
仅「待发货」可发货 → 变为「待收货」。非卖家 `404`。

### PUT /orders/{orderNo}/confirm · 确认收货（需登录，仅买家）
仅「待收货」可确认 → 变为「已完成」。

## 六、支付

### POST /pay/create · 创建支付单（需登录）
请求 `{ "orderNo": "CT...", "payMethod": "0" }`（`payMethod`：0沙箱 1支付宝 2微信 3余额，默认沙箱）。
返回 `data`：`{ payNo, orderNo, amount, payMethod, payMethodLabel, status, statusText, thirdPartyNo, createTime, callbackTime }`

### GET /pay/{payNo}/status · 支付状态（需登录）
返回同上结构。非本人支付单 `404`。

### POST /pay/{payNo}/confirm · 沙箱支付确认（需登录）
演示环境直接置为**支付成功**，生成第三方流水号，并把订单推进为「待发货」。
**幂等**：重复调用直接返回「支付成功」，不会重复推进。

## 七、退款 / 售后

### POST /orders/{orderNo}/refund · 申请退款（需登录，仅买家）
请求 `{ "reason": "商品与描述不符" }`
订单转「退款中」，退款单状态「待审核」。
仅「待付款 / 待发货 / 待收货」可申请；重复申请 `409`。

### GET /refunds · 我发起的退款（需登录）
### GET /refunds/incoming · 我作为卖家待处理的退款（需登录）

### POST /refunds/{refundNo}/agree · 卖家同意（需登录）
仅「待审核」可同意 → 「已同意」。

### POST /refunds/{refundNo}/reject · 卖家拒绝（需登录）
请求 `{ "remark": "商品没问题" }`
退款单「已拒绝」，**订单回滚为申请退款前的状态**。

### POST /refunds/{refundNo}/complete · 确认退款到账（需登录）
需先「已同意」。退款单「已退款完成」，订单「已退款」，并**恢复库存 / 商品重新上架**。

退款记录字段：`refundNo, orderNo, refundAmount, reason, status, statusText, buyerId, sellerId, handleBy, handleTime, handleRemark, createTime, orderStatus, orderStatusText`
